# Math-adversarial: exploratory probe matrix (opt-in)

This is a deliberately aggressive **exploration** of Hans Hagen's 2026-10-28
`texlinebreak.c` proposal, not a replacement for `math-basic` and
`math-extended`. It has no implicit default; use `--suite math-adversarial`.

- Deterministic, generated probes covering short/long inline math, positive,
  zero and negative math penalties, `noautobreak` and other glue flags,
  TeX/Lua glue, math surround, factor scaling, explicit force penalties,
  glue penalty fields, alternative widths and pre-inline control cases.
- The entire test matrix is generated by `src/context_testsuite/adversarial.py`.
  It is self-contained and has no dependency on NixOS-Config, Hans's source
  file, or the patched engine; engines are passed as executable paths.
- Compiles in independent, small PDF shards to preserve other evidence if a
  particular combination crashes a build. Experimental glue-penalty-field
  cases have separate shards (in case the Lua field isn't supported).
- Each case gets an index entry, PDF page, source, extracted body text,
  classification and (if flagged) a one-page `repros/Axxxx.tex`.
- Findings are ranked in `findings.md`, detailed data in `findings.json` and
  `observations.json`. Generated data are **local run artifacts**, not a
  manifest or export API for other repositories.

## Claims: keep three levels separate

1. `force-explicit`: An actual `\penalty-10000` node must break. This is
   stronger evidence than a Math-Penalty assumption, subject to extraction
   and the source actually creating the intended node sequence.
2. `protect`: A glue `noautobreak` flag with no forced penalty should
   suppress that automatic break. Here a split is a plausible failure; check
   the precise node list and full PDF before reporting a bug.
3. `force-math-unprotected`: A forced `\postinlinepenalty=-10000`
   followed by *ordinary glue* is a particularly useful probe.  If the
   candidate does not break there (e.g. A0419 at 80mm) but upstream does,
   this is independent of the disputed `noautobreak` precedence.  It is
   reported as a **high-priority semantic question**, not silently marked
   as a proven invariant violation.  Inspect the node's actual penalty.
4. `force-math-question`: `\postinlinepenalty=-10000` followed by protected
   glue may be logically contradictory to `noautobreak` priority. **This is
   intentionally labelled as a semantic question, not a proven bug.**
   The intended precedence needs explanation and verification by Hans.
5. `observe`: No semantic oracle. A change compared to upstream is simply
   an observation, never an automatic regression claim.

The checker uses the shared PyMuPDF observer, including page-count and
marker/follower validation. This does **not** inspect engine nodes or prove the origin of a
breakpoint. A visually plausible change can still be a misclassification.

## Run (inside the testsuite's `nix develop` shell)

```sh
context-testsuite run \
  --baseline ../NixOS-Config/result-context-unpatched/bin/context \
  --context ../NixOS-Config/result-context-hans/bin/context \
  --suite math-adversarial \
  --output results/hans-adversarial
```

To examine our own patch, replace `--context` and `--output` accordingly.
For a second opinion, run Hans vs our patch as well. Comparison directions
matter. Inspect `results/hans-adversarial/math-adversarial/findings.md` and
its `repros/` directory. A missing reference is allowed, but can't reveal
cross-version changes.

An `incomplete` result (exit code 2) means an entire shard failed or its PDF
text couldn't be classified. Inspect the extracted `cases.txt`, PDF and
build.log; don't mistake an extraction issue for a semantic failure. Exit code 1 indicates a provisional strong-invariant
candidate requiring manual confirmation. Exit code 0 means only that no
classified strong-invariant violation was found; semantic questions and
baseline differences can still be present in findings.

## Hans design-consistency probes (added 2026-10-28)

The original **A0001–A0450 IDs remain unchanged**. A0451 onward adds four
linked experiments, still run with `--suite math-adversarial` and still exported
with the existing `context-testsuite export --cases ...` command.

1. **`noautobreak-neighbors` (75)**: an ordinary space, `~`,
   `\nobreakspace`, and Lua glue with option 0 or 1 after `\math{12345}`,
   `\hbox{12345}`, or ordinary text `12345`. Compare direct adjacency,
   `\relax`, a zero kern, an explicit `\penalty0`, and
   `\penalty-10000`. In particular, **a break at the explicit penalty node
   does not violate `noautobreak`**: the flag blocks *automatic glue breaks*,
   not arbitrary explicit breakpoints. Cases containing such an intermediary
   are **observational** except the independently forced-break cases.
2. **`noautobreak-boundaries` (56)**: Math penalties -10000, -9999,
   -1, 0, 1, 9999, 10000 with normal/protected glue and two widths.
   Compare the expected `-10000` discontinuity with nearby values; deciding
   whether Math penalties should defeat `noautobreak` is still a hypothesis.
3. **`glue-penalty-field` (+48)**: Math penalty versus Lua `n.penalty`
   with the `glue_option_has_penalty` option deliberately disabled:
   `n.options` is assigned *after* `n.penalty` to keep the final options
   at 0 or 1 even if the Lua setter changes them. In Hans's
   helper, `glue_penalty(next)` is consulted regardless of that option.
   Does an inactive field change the *Math* breakpoint? The field is set
   through Lua; results must be inspected before asserting a bug.
4. **`glue-penalty-field` (+54)**: Same field comparison together with
   `\mathinlinepenaltyfactor`. Hans's early return may skip scaling;
   the factor's semantics and actual effects still require verification.

**Total: 683 probes.** The new field tests share the existing experimental
shards; the original tests remain intact. New *questions* are NOT automatically
new *hard invariant failures*. Inspect `observations.json` for comparisons
and `case-index.json` for `pair` labels. The current reporter doesn't
automatically group pairs, and it only checks the relationship after marker
`12345`. Therefore compare full extracted bodies and page images for any
interesting candidate, especially when a penalty breaks *before* the marker.

Suggested follow-up: run the same baseline against (1) Hans's engine and
(2) our patched engine, then prioritize differences in `noautobreak-neighbors`
and `glue-penalty-field` that cannot be explained by explicit breakpoints or
layout width. Don't email Hans a bare list of changed PDFs. Reduce a finding
to a one-page `.tex` proof with matching PDFs first.

## Follow-up: real paragraph-pass factors (A0684–A0779)

The earlier A0630–A0683 used `\mathinlinepenaltyfactor`, which does **not**
set the C linebreak property `properties->math_penalty_factor`. Do not use those
results as evidence about the early-return branch in Hans's helper. The new
96 cases activate `\parpasses 3` with the same `mathpenaltyfactor` in *every*
subpass and `\linebreakpasses=1`, varying 250/1000/2000/12000, positive
and negative math penalties, glue penalties, noautobreak, and frame width.
Consult the engine logs for pass execution before drawing conclusions.
**Total: 779 probes**; previous IDs remain unchanged.

The separate `glue-option-entry.tex` diagnostic logs fields after construction.
Its former Lua processor hook was removed. Verification at the actual C helper
requires the instrumented engine; use the isolated `diagnose` command.

Standalone, reader-friendly demonstrations are in `cases/math/diagnostics/`
for discussion with Hans. They are **candidate examples**, not yet certified
reproductions with the latest Hans engine.

The self-test `tests/test_pdf_extraction_parity.py` checks real archived PDFs.
Its optional historical Poppler cross-check needs `CTS_TEST_POPPLER=1` and a
separately installed Poppler; production uses only the shared PyMuPDF observer.
